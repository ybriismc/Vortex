Vortex

A Minecraft: Bedrock Edition proxy written in Go, built on top of Spectrum. YAML configuration, server balancing, packet filtering, transfer animations and an API for your downstream servers — in a single binary.

Go 1.25+ Spectral & QUIC Stateless MIT licensed
Download GitHub Changelog

Overview

Vortex packages Spectrum into a proxy that is ready for production. Spectrum handles the protocol — a single connection per downstream server, one stream per player, no RakNet between proxy and server — while Vortex adds everything an operator needs to run it.

Balanced discovery

Primary and fallback server pools with round robin, random or first strategies.

Packet guard

Per session rate limit, block list by packet identifier and a maximum packet size.

Transfer animations

Dimension, fade, smooth and ease, with the camera following the player.

API service

TCP service with secret authentication so servers can transfer and kick players.

Resource packs

Served once by the proxy, with content key support, and never re-sent on transfers.

Plugins

Loaded from plugins/ at startup, with an event bus, priorities and cancellable events.

Operations

Text or JSON logs, config validation on boot and a clean shutdown on SIGINT/SIGTERM.

Requirement: the servers behind the proxy must speak the Spectrum protocol — spectrum-df (Dragonfly) or spectrum-pm (PocketMine-MP). A plain RakNet Bedrock server cannot be used as a downstream server.

Architecture

Players hold a single RakNet connection to the proxy and never reconnect. Vortex swaps the server side of the session, which is why a server switch has no loading screen, no new handshake and no resource pack re-download.

┌──────────────────────────────┐ Player ──RakNet────▶│ Vortex (proxy) :19132 │ (one connection, │ discovery · guard · API │ never reconnects) └───┬───────────┬───────────┬──┘ │ spectral/quic — one connection per server, │ one stream per player ┌──────────▼─┐ ┌──────▼──────┐ ┌▼────────────┐ │ Lobby-1 │ │ BedWars-1 │ │ SkyWars-1 │ │ Lobby-2 │ │ BedWars-2 │ │ ... │ └────────────┘ └─────────────┘ └─────────────┘ (primary) reached through transfers

Login

The discovery picks an address from servers.primary using the configured balancer and the proxy dials it. Only the lobbies belong in the configuration file.

Lobby to gameplay

Gameplay servers are never listed in the proxy. The downstream server asks for the transfer, either through Spectrum's own Transfer packet (identifier 504) or through the API service. Vortex dials whatever address the transfer names, so adding a new gameplay server needs no proxy restart.

Failure

If the server a player is on dies, Spectrum falls back to an address from servers.fallback — usually the lobbies — instead of dropping the player. A transfer that fails simply leaves the player where they are and is logged with its origin and target.

Installation

From a release

curl -L -o vortex.tar.gz https://github.com/ybriismc/Vortex/releases/latest/download/vortex-linux-amd64.tar.gz
tar -xzf vortex.tar.gz
./vortex

From source

git clone https://github.com/ybriismc/Vortex.git
cd Vortex
make build
./vortex

The first run writes config.yml with the default values. Edit it and start the proxy again, or point the binary elsewhere with ./vortex -config /etc/vortex/config.yml.

resource_packs and logging

Packs are read from resource_packs.directory, optionally with content keys, and may be made mandatory. Logging takes a level (debug, info, warn, error) and a JSON toggle for log shippers.

Security

The guard is a Spectrum Processor attached to every session before its login sequence starts, so no packet reaches a server unfiltered.

KeyEffect
rate_limit.packets_per_secondBudget per session per second
rate_limit.actiondrop discards the excess, kick disconnects the player
blocked_packetsClient packet identifiers that never reach the server
decode_packetsIdentifiers the proxy fully decodes (Spectrum's client_decode)
max_packet_sizeMaximum size, in bytes, of a client packet
Blocking reads the identifier straight from the packet header, so a blocked packet is never decoded. Keep decode_packets as short as possible — every identifier in that list costs CPU on every packet of that type.

Any downstream server can ask for a transfer to any address, so keep the proxy, the servers and the API on a private network or VPN, and always set api.secret.

API

Spectrum's TCP service lets your servers and external tooling act on live sessions. Enable it under api, set a secret and connect with the client of your server implementation.

IDPacketEffect
0ConnectionRequestAuthenticates the server against the service
1ConnectionResponseAuthentication result
2KickDisconnects a player by username
3TransferTransfers a player to another address

On the game side, the Spectrum protocol packets (identifiers from 500) let a server request Transfer, Flush, Latency and UpdateCache directly on the session connection.

Transports

Both transports multiplex players as streams over a single UDP connection per server.

SpectralQUIC
BasePlain UDP, custom protocolRFC 9000, via quic-go
EncryptionNone — frames travel in the clearTLS 1.3 (certificate not verified)
HandshakeOne round trip, no cryptoTLS handshake
CPU costLowerHigher, encrypts every packet
Congestion controlReno and Cubic, pacing, MTU discoveryCubic
MaturitySmall project, Go and PHPIETF standard, widely tested

Use spectral when the proxy and the servers share a private network — it is the cheapest option. Use quic when the traffic leaves that network. The setting is global: every downstream server must listen on the same transport.

Plugins

Vortex has a plugin API: a plugin subscribes to proxy events — login, join, quit, server selection, transfer, chat, commands — and acts on the proxy through a small interface (transfer, kick, message, broadcast, edit the server pools).

Plugins are built with go build -buildmode=plugin and dropped in the plugins/ directory: the proxy loads them at startup, with no rebuild and no imports to edit. Go requires the proxy to be built with cgo (the Linux releases are), the platform to be Linux or macOS, and the plugin to be built against the same Vortex version. A plugin can also be compiled into the binary instead. 

func (w *Welcome) Load(ctx *plugin.Context) error {
    event.Subscribe(ctx.Bus(), func(e *event.PlayerJoin) {
        w.proxy.Broadcast("§e" + e.Session.Client().IdentityData().DisplayName + " joined!")
    }, event.Normal)
    return nil
}

Pterodactyl

Import pterodactyl/egg-vortex.json in the panel under Nests → Import Egg. The install script downloads the release build for the node's architecture and writes a default config.yml; the panel keeps proxy.addr in sync with the allocated port. To update the proxy, change VERSION and reinstall the server.

Private hosts

On a VPS or dedicated machine, start.sh installs what is missing (Go, git, curl), builds the binary, creates the configuration file and starts the proxy. 

./start.sh              # install, build and start
./start.sh --no-build   # start the existing binary
./start.sh --update     # pull the repository, rebuild and start
./start.sh --tune       # also apply the kernel network tuning (needs root)
./start.sh --help       # every flag

The script installs Go into ~/.local/go when the system package is missing or too old, so it works without root on most hosts.

Kernel tuning

Under heavy load the default Linux network buffers are too small for a UDP proxy and cause random errors and disconnections. Raise them before going to production: 

sysctl -w net.core.rmem_max=7500000
sysctl -w net.core.wmem_max=7500000
sysctl -w net.ipv4.tcp_rmem="4096 87380 7500000"

Persist the values in /etc/sysctl.d/, or run ./start.sh --tune.
